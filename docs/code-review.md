# 代码检查记录 · 1.2

检查了扫描引擎、目录发现、数据模型、扫描状态与取消、六类 SwiftUI 页面、命令卡片、资源与发布脚本。

| 发现 | 本次处理 |
| --- | --- |
| 重叠根目录的保留结果取决于配置顺序；子目录先出现时会留下冗余位置 | 标准化、去重并先处理父目录，统一位置与统计归属；增加反向顺序回归测试。 |
| 单个归档文件作为扫描根时，最大的子项路径会错误地再拼接一次文件名 | 文件根使用自身路径，增加独立归档测试。 |
| 为每个普通文件存储 inode，扫描大缓存时会增加内存占用 | 仅为多硬链接文件保留 identity 集合；不重叠的单链接文件无需去重记录。 |
| 目录发现错误在列表中按 Google 路径字符串筛选，扩展 Conda 后会遗漏 | 错误携带生态和数据类型，列表按分类展示。 |
| Cargo 仅统计压缩包，遗漏源码、索引与 Git 依赖 | 补充官方列出的缓存子目录，解释离线依赖与本地修改风险。 |
| JetBrains 系统目录的说明未明确本地历史 | 补充本地历史不可由重新索引恢复的说明。 |
| 通用符号不能准确代表语言和开发工具 | 换成由原始 SVG 转换并保留矢量表示的 PDF 品牌图标，应用标识重画为显示器与扫刷，并使用矢量 PDF；保留来源与许可证，没有对应资源的工具使用合适的系统符号。 |
| DMG 隐藏扩展名选项给应用附加 FinderInfo，导致包内签名检查失败 | 取消对已签名应用附加 FinderInfo，保留原应用签名；构建脚本自动只读挂载，验证包内签名、二进制与资源一致性及 Applications 链接。 |
| 版本号在侧栏写死 | 改为读取应用 Bundle 版本。 |
| 打包入口依赖手动先构建、版本在 Xcode 配置中重复维护，缺少 CI 与标签发布 | 参考 QuietLock，集中版本到 `Config/Version.xcconfig`；DMG 默认构建并检查双架构，使用独立 Python 环境与固定依赖，输出稳定名称和 SHA-256；新增 PR / main CI、版本标签发布及本地发布预演脚本。 |

扫描仍限制 4 路并发，循环检查取消；不跟随符号链接、不扫描主目录外的路径，采用分配块统计并在工具内去重硬链接。Conda 仅发现包归档和索引，不扫描完整运行环境。

验证：17 项核心测试通过，覆盖权限错误、取消、符号链接、硬链接、隐藏文件、重叠目录、独立文件、稀疏文件、IDE 版本发现、Conda 筛选和敏感目录排除。arm64 / x86_64 发布构建、应用签名验证和 DMG 完整性检查通过，并实际打开检查了图标和安装布局。资源检查确认 35 个品牌图标及应用内标识共 36 项均保留矢量表示，品牌 PDF 不含嵌入位图。

本次未运行任何清理命令，未删除用户的开发缓存或环境。已知统计限制：APFS 共享块、快照、扫描期间的文件变化与自定义路径仍会影响统计；这些在说明中保留。
